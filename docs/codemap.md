# Codemap — what exists, where, and its honest status

Consult at the start of a task; update in the SAME commit that changes a
subsystem. Companion registries: `docs/re-frontier.md` (ordered RE progress,
real vs hack) and `docs/info/` (claims + instruments).

Direction is **static recompilation + native overrides**, and as of 2026-08-05
the **PC build is the live front again** (C078). The reason is not preference:
on the PC path the game *already runs*, so functions move from "forwarded to
the original DLL" to "our recompiled C" while it keeps working; on the Xbox
path nothing works until everything does, and its GPU boundary is NV2A push
buffers, which [`strategy.md`](strategy.md) calls "the xemu problem". The Xbox
work is real and kept (it boots deep into engine setup with a clean register
file) but it is not the shortest road to a playable port. Status words mean:
**verified** = checked against the original on real data, with the check cited ·
**partial** = works, with a named gap · **untouched** = not started.

RCR is not exotic: MSVC's 64-bit division helpers halve a value with `shr edx,1; rcr eax,1`, so any guest that divides a long long reaches it, and the game did. The set implemented is the one the shipped modules actually contain, counted rather than guessed -- MOVAPS/MULPS/SHUFPS/MOVSS/ADDPS lead at over 600 uses each -- and the arithmetic calls the HOST's SSE on purpose: the host is x86-64, the guest instruction IS the host instruction, and hand-written float code would differ exactly where it is hardest to notice (MINPS returns its SECOND operand on a NaN or -0.0/+0.0, and RCPPS/RSQRTSS are approximations the game's own Newton-Raphson steps are written around). What IS written out is the part a wrong reading gets wrong silently -- which lanes each form writes and preserves, which operand supplies which half -- and `tests/test_sse.c` checks all of it against the CPU's own instructions: 30,101 comparisons over a corpus of NaNs, signed zeros, infinities and denormals, all 256 SHUFPS immediates, and a discriminator proving the corpus can tell hardware MINPS from `fminf`. `xmmword ptr` operands and the SSE2 forms of MOVD/MOVQ parse; LOOP/LOOPE/LOOPNE are translated (ECX decrements before the test and the FLAGS are untouched, which `DEC ECX; JNZ` gets wrong). PUSHAD/POPAD are translated too, with unit tests aimed at their two invisible failures: PUSHAD pushes the ESP from BEFORE the pushes (four decrements too late stores a value 16 bytes low, and POPAD DISCARDS that slot, so nothing would ever complain), and POPAD SKIPS it rather than restoring it (restoring would undo the four pops after it, leaving EBX/EDX/ECX/EAX read from the wrong words). What remains is 3DNow! -- an AMD path selected on CPUID, and not taken on any run so far -- plus AAA/DAA/BOUND/XLAT/ENTER, which are almost all inside `FUN_0064252b` and `FUN_00642e70`, the two bodies that run into a DATA table embedded in `.text`.
